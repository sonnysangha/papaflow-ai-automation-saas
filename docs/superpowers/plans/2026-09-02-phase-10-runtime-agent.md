# Phase 10 — Runtime Agent (eve) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development — one Opus subagent per task. The spike runs FIRST in the scratchpad; nothing lands in the repo until every checkpoint below passes.

**Goal:** An Agent node backed by an eve agent whose tools are built per session from the org's connections, with the model coming from the org's own AI connection (BYOK) or a house model via AI Gateway; tool calls appear as sub-rows under the node.

**Verified facts (docs/research/eve.md, versions.md — re-verify against `node_modules/eve/docs/README.md` after install):** `eve 0.49.0` (never `eve@beta`), Node ≥ 24, ESM-only, peer `ai ^7.0.82`; two agents in one Next app via `withEve(nextConfig, { agents: { runtime: "./agents/runtime", builder: "./agents/builder" } })` from `eve/next`, each at `/eve/agents/<name>/eve/v1/*`; `next dev` spawns the eve dev server (no second terminal); `next.config.mts` required; `proxy.ts` already excludes `eve/`; production fails closed without `agents/<name>/channels/eve.ts` exporting `eveChannel({ auth: [clerkAuth(), localDev()] })` from `eve/channels/eve` (+ `extractBearerToken`, `localDev` from `eve/channels/auth`); `defineAgent({ model })` from `eve`; `defineTool` from `eve/tools`; `defineDynamic` from `eve/tools` returning per-session tools on `session.started` (tool closures hold only ids); model selection: `session.started`/`turn.started` handlers return model-ID strings, a live AI SDK model only from `step.started`; client `new Client({ host: `${APP_ORIGIN}/eve/agents/runtime`, auth: { bearer }, redirect: "manual" })` from `eve/client`, `sessions.create({ message, outputSchema })` → `await response.result()` → `{ status, message, data }`.

## Spike (scratchpad, throwaway)
1. `pnpm add eve@0.49.0` in a copy of the repo (or a fresh `npx eve@latest init spike` project) and read `node_modules/eve/docs/README.md`; diff the API against the facts above and write the differences into `docs/research/eve-spike.md`.
2. `next.config.mts` with `withEve(withWorkflow(cfg), { agents: { runtime: "./agents/runtime" } })`: `next dev` must serve `GET /eve/agents/runtime/eve/v1/health` AND `POST /.well-known/workflow/v1/flow` (non-404). If not, swap the wrapper order and record it.
3. `agents/runtime/channels/eve.ts` with a Clerk authenticator: verify the bearer with `@clerk/backend` (read `node_modules/@clerk/backend/dist/index.d.ts` — Core 3 exports `verifyToken`), return `{ authenticator: "clerk", principalId: sub, principalType: "user", attributes: { orgId, plan } }`; an unauthenticated `POST …/eve/v1/session` must be rejected, an authenticated one accepted.
4. `defineDynamic` returning one tool from a fake connection list; a session that calls it; the `step.started` model handler returning `providerFor(...)` for a BYOK key (use an env key only in the spike); a Gateway string fallback from `session.started`.
5. `eve/client` from a Node script: `sessions.create({ message, outputSchema })` → structured `data`.
6. `vercel build` (or `vercel deploy --dry`) emits both the workflow functions and the eve services.
