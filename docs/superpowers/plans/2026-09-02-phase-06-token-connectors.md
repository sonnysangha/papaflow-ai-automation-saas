# Phase 6 — Token Connectors and Action Nodes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development — one fresh Opus subagent per task. Tests first for every connector `test()`/node `run()` with mocked `fetch`.

**Goal:** Users connect Discord (webhook and bot), Slack (bot token), Notion (internal integration token), Airtable (PAT), Linear (API key), GitHub (PAT), Microsoft Teams (workflow URL) and optionally their own Resend account, all as per-org connections, and post/create through them from action nodes. Pickers (channels, chats, data sources, bases) call the provider server-side with the fresh token and return non-secret lists.

**Architecture:** Phase 4's `defineConnector` (fields, `test()`, `discover()`, optional `afterCreate`) + `nodes/actions/*` with `credential: "<provider>"`. `/api/connections/[id]/pick` runs a provider-specific picker (`connector.pick?.(kind, secret, meta)`) so the config panel can offer dropdowns without exposing tokens. Every node maps provider errors to `ConnectorError(status, retryAfter)`.

**Spec:** master plan Connection model + Phase 6; `docs/research/connectors-chat.md` and `docs/research/connectors-data.md` (verified endpoints, headers, limits, 2026 changes).
