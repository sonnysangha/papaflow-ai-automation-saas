# critic:conflicts

The eight research domains agree on the core pin set (next 16.3.4 / react 19.2.8 / convex 1.45.0 / @clerk/nextjs 7.8.4 + @clerk/backend 3.17.0 / @xyflow/react 12.11.6 / zod 4.5.4 / ai 7.0.90 / workflow 5.0.0-beta.47 / eve 0.49.0 / @ai-sdk/workflow 2.0.21) and every peer range checks out (Clerk peers next ^16.1.0-0 and react ~19.2.3; convex peers react ^19 optional; ai/eve/openrouter/@ai-sdk/* all accept zod ^4.1.8; eve peers ai ^7.0.82 and has no workflow dep; @ai-sdk/workflow pins ai 7.0.90 exactly and peers workflow ^5.0.0-beta.42). The real problems are (1) three domains each own a piece of one file — proxy.ts — and Clerk's recommended matcher does not exclude `.well-known/workflow/` or `/eve/`, which the Workflow and eve domains both require; (2) next.config must be `.mts` because `eve/next` is ESM-only, while three domains' snippets still write `next.config.ts`, and the withEve/withWorkflow order is undocumented (PLAN says withWorkflow(withEve()), eve domain says withEve(withWorkflow())); (3) the Clerk-webhook-in-Convex plan relies on svix 2.2.0 whose `verify()` now returns undefined, and `@clerk/backend/webhooks` `verifyWebhook` is the cleaner replacement; (4) PLAN's billing sync assumes `is_free_trial` on the webhook payload (absent from the TS type), a plan slug called "Free" (Clerk's auto-created default is `free_org`) and camelCase statuses (payload uses `past_due`); (5) the Convex identity story is contradictory across domains — Clerk domain expects dotted `identity['o.id']`, Convex domain found the OIDC keybroker stringifies nested claims, and neither Clerk shortcode page documents `{{org.id}}`/`{{org.role}}` — so the plan must not depend on shortcodes and must log the identity once; (6) eve's `defineDynamic` cannot return a live AI SDK model from `session.started` (strings only; live models only from `step.started`), which breaks PLAN's per-org BYOK model design as written; (7) v5 Workflow SDK relaxed two of CLAUDE.md rule 4's absolutes (`start()` is step-backed and callable in workflow bodies; `process.env` is readable as a frozen snapshot) and renaming `runNode` does not break in-flight Vercel runs; (8) PLAN L252's AAD uses userId while CLAUDE.md rule 2 uses orgId. Toolchain pins the plan author should reconcile: typescript 5.9.3 (template) or 6.0.3 — never 7 (typescript-eslint peers <6.1.0); eslint 9.39.5 — never 10 (eslint-config-next's plugins peer ^9); package.json `engines.node` "24.x" (eve needs >=24) rather than the ai-sdk domain's ">=22"; do not install @clerk/themes (Core 2 line; use @clerk/ui 1.31.0). Exact CLAUDE.md and PLAN.md edits follow as info items.
