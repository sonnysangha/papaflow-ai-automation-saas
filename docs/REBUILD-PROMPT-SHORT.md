# PapaFlow — the short rebuild prompt

> Two paragraphs. Paste as the opening message of a fresh session in an empty directory. For the
> full specification see [`REBUILD-PROMPT.md`](REBUILD-PROMPT.md).

---

Build **PapaFlow**, an n8n-style multi-tenant workflow-automation SaaS, from an empty directory. Organisations (Clerk Organizations, no personal-account mode) draw workflows on a React Flow canvas or describe them to a Pro-only AI Builder, add their own AI keys and app credentials as encrypted per-organisation connections, press Run to test, and Publish so webhooks, hosted forms, schedules and Slack/Telegram/Stripe events start runs. Stack, pinned exactly: Next.js 16.3.4 App Router with React 19.2, Tailwind v4 and shadcn on Base UI; Convex 1.45 for all state and live subscriptions; Clerk v7 (Core 3) for auth, organisations and B2B billing with `free_org`, `pro` and `team` plans gating feature slugs; Vercel Workflow SDK 5.0.0-beta.47 for durable runs; eve 0.49 for two agents (a Runtime agent behind the AI Agent node whose tools are built per session from the org's connections, and the Builder agent that edits the workflow live through Convex mutations and asks for credentials with a durable `ask()`); AI SDK 7 with direct provider packages; zod 4; vitest. Ship 27 node types (Manual, Webhook, Form, Schedule, Telegram and Stripe triggers; If, Route by value, Set values, Pause, Wait for a callback, Ask for approval with chat buttons, For each; LLM, Classify, Extract, AI Agent; HTTP, email, Slack, Discord, Telegram, Teams, Notion, Airtable, Linear, GitHub), 21 bring-your-own-key connectors with model and channel pickers discovered at connect time, 13 templates, a canvas whose nodes and edges light up as steps run with a runs timeline underneath, undo/redo, tidy-up auto-layout and needs-setup badges, runs pages with stats, filters and a step-level detail sheet, custom pricing cards on Clerk's `CheckoutButton`, landing/pricing/docs/auth pages, a light/dark/system theme, full mobile responsiveness, and a production deployment on Vercel with a Convex production deployment and a flagship README.

Non-negotiables: a run is a Vercel Workflow (`runGraph`, orchestration only — no I/O) whose single idempotent step (`runNode`) resolves `{{ node.field }}` templates, opens the credential inside the step (AES-256-GCM, AAD `orgId:connectionId`, key from `CREDENTIALS_KEK`), does the call, maps 429 to retryable and other 4xx to fatal, and writes step rows to Convex through `ENGINE_SECRET`-guarded mutations; secrets never reach a model, a step argument or result, a client query or a log, and only the last four characters exist in the clear. Clerk is the source of truth for orgs, members and plans — no mirror tables, no webhook; Convex reads the `pla`/`fea` session claims, the session-less engine asks Clerk's Backend API, and gating runs on three layers (`<Show>` in the UI, `has()` in routes, Convex plan limits plus `runNode` refusing gated nodes). Publish is the only switch for triggers, and schedules use Convex as the alarm clock: one durable scheduled job per published schedule POSTs a `schedule-tick` route that re-checks, starts the run and hands back the next occurrence to arm. Nothing reachable from the workflow may import `node:*`; Clerk's middleware must exclude `/.well-known/workflow/` and `/eve/`; every third-party credential is a connection, never an env var. Never guess an API — read the installed packages' docs and types first; keep the pins; plan each phase, finish it green on typecheck, lint and tests with a real browser check and one conventional commit; stop only for a secret I must paste or a dashboard-only step, and never pass a secret through chat.
